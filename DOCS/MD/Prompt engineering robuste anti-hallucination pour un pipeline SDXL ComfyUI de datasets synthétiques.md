# Prompt engineering robuste anti-hallucination pour un pipeline SDXL/ComfyUI de datasets synthétiques (Illustrious / NoobAI / fabricatedXL)

## TL;DR
- Le problème de « remplissage halluciné » d'une main vide sur un guide ControlNet peu contraint n'est pas d'abord un problème de prompt : c'est un problème de **prior de données** (sur Danbooru, le concept « hand » est massivement co-occurrent avec « holding [objet] »), à corriger sur trois leviers simultanés — (1) contraindre positivement la pose de main avec des tags Danbooru explicites (`own_hands_together`, `outstretched_hand`), (2) suppression négative renforcée des objets (`holding, object, phone, cellphone, cup`) via NegPiP ou NAG plutôt que le négatif CFG classique, et (3) masquage spatial du conditionnement négatif et/ou renfort local du ControlNet sur la zone de la paume.
- Pour la génération batch de datasets, la fiabilité vient de la **structure et du déterminisme** : tags Danbooru normalisés séparés par virgules (jamais du langage naturel type « reaching toward X »), seed stable sur les wildcards, `ban_tags` regex dans TIPO/DanTagGen, et un format de prompt versionné et figé (format Kohaku-XL-Zeta `<|special|>...<|quality|>`).
- L'état de l'art des garde-fous : TIPO (arXiv 2411.08127) et DanTagGen exposent un champ **`Ban tags` (blacklist regex)** qui est le mécanisme direct pour empêcher l'upsampler d'introduire des objets non désirés ; côté suppression, **NAG (Normalized Attention Guidance, arXiv 2505.21179)** dispose désormais d'un node ComfyUI (`ChenDarYen/ComfyUI-NAG`, plus un node natif `NAGuidance`) qui « restaure un negative guidance efficace là où le CFG s'effondre ».

## Key Findings

1. **Le phénomène est documenté comme un problème de prior, pas de prompt.** La littérature sur l'inpainting nomme précisément « unwanted object insertion » le fait qu'un modèle de diffusion remplit une zone masquée avec des éléments aléatoires non alignés sur le contexte (ASUKA, arXiv 2312.04831, qui décrit « the unwanted object insertion problem, where the model generates random, unreasonable elements to fill masked regions » ; ControlFill, arXiv 2503.04268, qui note que pour retirer un objet « the diffusion process might inadvertently introduce another object into the masked area »). Sur les modèles anime, la cause racine est la co-occurrence Danbooru « hand ↔ holding object ». Une paume lisse dans un guide OpenPose/depth est simplement « sous-contrainte » : le modèle retombe sur son prior le plus probable, une main tenant un objet.

2. **La suppression négative classique (liste de tags dans le négatif CFG) est intrinsèquement peu fiable.** Un papier de 2026 (« Orthogonal Negative Guidance in Attention Feature Space ») montre quantitativement que la négation par prompt peut échouer, voire *générer* la cible à supprimer (score de suppression 3,88 pour « Prompt Negation » vs 86,88 pour leur méthode sur FLUX-dev). Les techniques 2025-2026 opèrent dans l'espace d'attention : **NAG**, **Perp-Neg** (arXiv 2304.04968), et **NegPiP** (poids négatifs dans le prompt positif).

3. **Le contrôle spatial du négatif existe et est le levier le plus précis pour une zone « paume ».** `ConditioningSetMask` + `ConditioningCombine` permet d'appliquer un conditionnement (positif OU négatif) uniquement sur une région masquée. Combiné à Attention Couple / NegPiP, on peut injecter « holding, object » en négatif *uniquement* sur le masque de la paume.

4. **Le ControlNet supporte un masquage de force spatialement variable et un scheduling temporel** via `ComfyUI-Advanced-ControlNet` (Kosinkadink) : `mask_optional` (masque d'attention gris = force locale variable), Timestep Keyframes (scheduling de la force au fil des steps), et Latent Keyframes. La convention communautaire pour OpenPose est `start_percent=0.0`, `end_percent≈0.75-0.85` pour laisser les derniers steps ajouter le détail organique.

5. **TIPO/DanTagGen exposent un garde-fou natif `Ban tags` (regex).** C'est le mécanisme officiel pour empêcher l'upsampler d'ajouter des objets. Alternatives 2026 : DART (sd-danbooru-tags-upsampler de p1atdev, avec « range ban tags »), et les nodes LLM locaux (Ollama Qwen) qui permettent un system prompt personnalisé avec liste d'exclusion.

## Details

### 1. Negative prompting et contrôle spatial anti-hallucination

**Pourquoi le négatif CFG seul ne suffit pas.** L'approche par défaut consiste à mettre les objets indésirables dans le negative prompt (ex. `holding, object, phone, cellphone, cup`). Ce sont de vrais tags Danbooru à très fort compte — `holding_hands` 99 135 posts, `phone` 95 781, `cellphone` 76 218, `holding_cup` 64 587 (comptes danbooru:General, source CSV d'autocomplete `LuKoi/ComfyUI-Custom-Scripts` sur HuggingFace) — donc ils portent un signal fort sur Illustrious/NoobAI. Mais le négatif CFG est global et souffre du « biais vers le prompt principal » : quand il y a chevauchement sémantique entre positif et négatif (une main EST présente, on ne veut pas qu'elle tienne quelque chose), le négatif peut être inefficace, voire contre-productif — c'est précisément ce que résolvent Perp-Neg (composante perpendiculaire du score négatif par rapport au prompt principal) et NAG.

**NAG (Normalized Attention Guidance) — l'outil 2026 clé.** Papier arXiv 2505.21179, titre exact « Normalized Attention Guidance: Universal Negative Guidance for Diffusion Models » (Dar-Yen Chen, Hmrishav Bandyopadhyay, Kai Zou, Yi-Zhe Song ; University of Surrey / NetMind.AI), soumis le 27 mai 2025 (v3 révisée 3 juin 2025), avec une page poster NeurIPS 2025 (neurips.cc/virtual/2025/poster/117946). Le résumé décrit « an efficient, training-free mechanism that applies extrapolation in attention space with L1-based normalization and refinement. NAG restores effective negative guidance where CFG collapses while maintaining fidelity ». Mécaniquement, NAG extrapole les features positives Z+ et négatives Z-, avec normalisation L1 et blend α. Implémentation ComfyUI : repo officiel `ChenDarYen/ComfyUI-NAG` avec les nodes `KSamplerWithNAG (Advanced)`, `SamplerCustomWithNAG`, et `NAGGuider` ; paramètres `nag_scale` (défaut 5.0), `nag_tau`, `nag_alpha`, `nag_sigma_end`. Un node natif ComfyUI `NAGuidance` existe aussi (docs.comfy.org). Support SD1.5→SDXL, SD3, FLUX, etc. Pour le cas d'usage (suppression d'objet phantôme dans une main), NAG appliqué à un négatif `holding, object, cup, phone` est nettement plus robuste que le négatif CFG.

**NegPiP (poids négatifs dans le prompt positif).** Via `pamparamm/ComfyUI-ppm` (node CLIPNegPip) : on peut écrire `(holding,:-1.3) (object:-1.1)` directement, ce qui permet une négation token-level plus chirurgicale que la liste négative globale. L'auteur recommande de garder les virgules à l'intérieur des parenthèses de poids (`(worst quality,:-1.3)` plutôt que `(worst quality:-1.3),`).

**Contrôle spatial du négatif (masquage régional).** Le node `ConditioningSetMask` (natif ComfyUI) applique un conditionnement à une région définie par un masque grayscale (blanc 255 = applique, noir 0 = ignore), puis `ConditioningCombine` fusionne. On peut donc créer un masque de la zone « paume » et y appliquer un conditionnement négatif spécifique. Attention Couple (`A8R8_ComfyUI_nodes` / `pamparamm/ComfyUI-ppm` AttentionCouplePPM) offre le même effet en espace d'attention avec des masques bounding-box (`LatentToMaskBB`), avec un `global_prompt_weight` réglable (0.01-1.0). Recommandations communautaires pour éviter le « bleed » : feathering de masque 15-30 px, denoise modéré (0.45-0.60), garder les prompts régionaux distincts et éviter les attributs globaux.

**Recherche académique de pointe (contexte, pas encore packagé pour prod).** MaskAttn-SDXL (arXiv 2509.15357, Chang et al., 18 sept. 2025) apprend un masque binaire par couche injecté dans les logits de cross-attention avant softmax, pour « sparsify token-to-latent interactions so that only semantically relevant connections remain active » — c'est la formalisation directe de « supprimer l'attention d'un token (ex. objet) sur une zone spatiale ». EliGen (arXiv 2501.01097, regional attention sur FLUX) et le papier e-commerce ControlNet mask-guidance (arXiv 2409.09681, qui multiplie un masque à chaque couche de l'encodeur UNet de ControlNet pour « effectively isolating the influence of the background ») complètent ce paysage. Aucun n'a de node ComfyUI prêt-à-l'emploi confirmé.

### 2. Prompt engineering robuste pour batch/dataset synthétique

**Bannir le langage naturel ambigu.** Les guides de référence Illustrious/NoobAI (Style Explorer de ThetaCursed ; guide Civitai d'Arctenox ; doc SeaArt NoobAI) convergent : « Comma-separated normalized Danbooru tags work best. Avoid long natural-language sentences for maximum adherence. » Une formulation comme « reaching toward camera » est doublement risquée : (a) c'est du NL faiblement représenté sur Danbooru, (b) « reaching » active le prior « holding ». À remplacer par des tags de pose de main explicites et fermés.

**Vocabulaire Danbooru de main « vide »/ouverte (confirmé).** Tags réels à fort compte utilisables en positif pour donner au modèle une pose de main *définie* (donc pas de retombée sur « holding ») : `own_hands_together` (76 136 posts, danbooru:General), `outstretched_hand` (~23 662), `outstretched_arm` (63 721), `interlocked_fingers`, `own_hands_clasped`, `pov_hands` (22 408, pertinent pour les plans POV/vers-caméra) — comptes issus du CSV d'autocomplete `LuKoi/ComfyUI-Custom-Scripts` (HuggingFace), miroir des comptes Danbooru. Les tags `empty_hands`, `open_hand`, `spread_fingers`, `showing_palm` sont plausibles mais à vérifier directement sur danbooru.donmai.us/wiki_pages avant de figer les conventions (existence/comptes non confirmés). La logique communautaire (« si un tag Danbooru a 1k+ images, le modèle sait probablement le générer », aituts / wiki.monai.art) s'applique. Ressource utile : la collection de tags d'actions main/bras testée sur waiNSFWIllustrious par はいぱーさんかく (note.com/vivid_walrus6061/n/n9877a06778e0).

**Ordre des tags et dilution.** Le guide Arctenox rappelle qu'Illustrious a ~248 tokens et que « the more further along a tag is in a prompt the more diluted it is » : placer les tags critiques (pose de main, main vide) en tête. Pour un dataset HandSegNet/FootSegNet où l'absence d'objet parasite est critique, la pose de main est un tag de premier rang, pas un détail de fin de prompt.

**Réglages checkpoint.** fabricatedXL_v70 (Civitai model 1203050, publié 5 janv. 2026, base Illustrious, merge de WAI-illustrious-SDXL + v6.0, Clip Skip 2, hash AutoV2 767CBC9DAA) suit les conventions Illustrious : quality tags `masterpiece, best quality, amazing quality, very aesthetic, absurdres` ; CFG bas (4.5-6.5 typique Illustrious, encore plus bas en v-pred NoobAI ~3.5) ; 28-35 steps. Pour un dataset, figer sampler + scheduler + CFG + steps est aussi important que le prompt.

**Déterminisme batch.** `ComfyUI-stable-wildcards` (seed stable → mêmes substitutions reproductibles) est essentiel : sans lui, les wildcards cassent la reproductibilité entre runs. Coupler avec un seed maîtrisé sur TIPO (le README indique que TIPO n'est pas déterministe sauf seed fixe, du fait du sampling temperature/top-k/top-p).

### 3. Systèmes d'upsampling de prompt et garde-fous

**TIPO (KGen / KBlueLeaf).** arXiv 2411.08127 (Shih-Ying Yeh, Sang-Hyun Park, Giyeong Oh, Min Song, Youngjae Yu) ; le dépôt KGen le référence comme « TIPO (ICLR 2026) » avec un lien OpenReview (à considérer comme annoncé par les auteurs — non confirmé par une source tierce indépendante). Entraîné sur **30M entrées** (« more than 25M entries have NL caption, more than 18M entries have tags », Danbooru + Coyo/GBC NL). Gère tags ET langage naturel. Le node ComfyUI (`utils/promptgen`) et l'extension `z-tipo-extension` exposent les options critiques : **`Ban tags` (blacklist, regex supporté)** = le garde-fou direct contre l'insertion d'objets ; `tag length` (short/long recommandés) ; `Prompt Format` (défaut = format Kohaku-XL-Zeta avec balises `<|special|>`, `<|characters|>`, `<|copyrights|>`, `<|artist|>`, `<|general|>`, `<|meta|>`, `<|quality|>`, `<|rating|>`, `<|generated|>`, `<|extended|>`) ; `temperature` (bas = meilleure cohérence entre tags). Pour un pipeline anti-hallucination : mettre `holding|object|cup|phone|cellphone|camera|bottle|weapon|gun` dans Ban tags, et baisser la température.

**DanTagGen (DTG).** Précurseur de TIPO, LLaMA 400M entraîné sur les 5M posts top-75% favoris de Danbooru. Nodes : `huchenlei/ComfyUI_DanTagGen`, `toyxyz/a1111-sd-webui-dtg_comfyui`, `Aaron-CHM/ComfyUI-z-a1111-sd-webui-DanTagGen` (ce dernier expose top_p/top_k). Même mécanisme de ban tags.

**DART / sd-danbooru-tags-upsampler (p1atdev).** LLM léger, options « variety level » et « range ban tags » (v0.2.0, 29 fév. 2024). Portage ComfyUI : `rookiestar28/ComfyUI-Danbooru-Tags-Upsampler` (supporte seed reproductible 0-4294967295, temperature, top_k, top_p, num_beams).

**LLM locaux comme upsampler contrôlable.** `jluo-github/comfyui-ollama-image-to-prompt` (Qwen3.5/Qwen3-VL/Gemma via Ollama, presets « Danbooru tags », seed déterministe) et `btitkin/ComfyUI-RandomPromptBuilder` (GGUF local, formats Pony/SDXL/Danbooru/Flux, injection auto de quality tags, support BREAK). L'avantage d'un LLM local avec system prompt : on peut y écrire explicitement la liste d'exclusion et les conventions maison — c'est le pont vers l'axe 4.

### 4. Structurer un « skill » / base de connaissance de prompt engineering réutilisable

Il n'existe pas (à la date de recherche) de standard formel unique, mais des patterns convergents :
- **Fichiers de wildcards versionnés** : format `sd-dynamic-prompts` (adieyal), utilisable dans A1111/Fooocus/ComfyUI ; ex. `X779/Danbooruwildcards` (wildcards Danbooru versionnés sur HuggingFace, explicitement conçus pour être couplés à TIPO). C'est le format de facto pour figer un vocabulaire de tags réutilisable.
- **Format de prompt figé** comme convention d'équipe : le format Kohaku-XL-Zeta (`<|quality|>`, `<|general|>`...) sert de schéma versionnable et documentable.
- **System prompts LLM** : `anima_pipeline` (Civitai article 27575) est un exemple concret d'UI qui pilote un LLM (LM Studio local / Gemini) via un system prompt pour construire des prompts Danbooru conformes, avec presets de personnages sauvegardés/chargés en JSON et auto-remplissage des tags depuis le Danbooru Wiki. L'article Civitai 15970 (« I Got Tired of Writing Tags ») documente le pattern « LLM local + workflow ComfyUI » où le LLM traduit une intention simple (« a cat made of circuit boards ») en tags techniques. Le retour d'expérience Zenn (platina) montre un Qwen2.5-14B-Instruct fine-tuné pour produire des pseudo-tags Danbooru avec few-shot.
- **Recommandation de structure de skill** : un document de référence versionné (git) contenant : (a) le lexique de tags autorisés/interdits (allowlist/banlist), (b) le format de prompt canonique, (c) les réglages figés par checkpoint, (d) des few-shot examples input→output — injectable comme system prompt dans un LLM local (Qwen/Mistral) ou directement mappé dans le champ `Ban tags` de TIPO.

### 5. ControlNet à faible contrainte locale

**Masquage de force spatialement variable.** `ComfyUI-Advanced-ControlNet` (Kosinkadink) : le paramètre `mask_optional` accepte un masque d'attention non-binaire — « decides what part of the image the controlnet to apply to (and the relative strength, if the mask is not binary) ». On peut donc *renforcer* localement la contrainte sur la paume (masque plus clair sur la main) sans complexifier le guide géométrique. Les « Soft Weights » (custom weights) répliquent « My prompt is more important » / « ControlNet is more important » (via `uncond_multiplier`).

**ControlNet strength scheduling.** Les Timestep Keyframes permettent de moduler la force au fil des steps (ex. force max sur les premiers steps pour verrouiller la structure, puis relâchement). Les Latent Keyframes modulent par latent dans un batch. Poser `strength=0` sur un keyframe bypass le calcul (gain de perf). Les keyframes se trient automatiquement par `start_percent`.

**Convention start/end percent.** Pour OpenPose (guides communautaires 2026) : `start_percent=0.0` (« Pose structure must be established in the earliest denoising passes — any later start causes irreversible compositional drift »), `end_percent≈0.75-0.85` (« Releasing ControlNet at 80% lets the model add natural skin, fabric, and lighting detail... Leaving at 1.0 produces stiff, over-rigid outputs »). Application directe au problème : relâcher le ControlNet trop tôt sur une zone sous-contrainte laisse le prior halluciner ; le garder plus longtemps + un masque de renfort local sur la paume contraint mieux.

**Choisir le bon ControlNet pour la main.** Pour une paume, un ControlNet **depth** (depth_zoe pour géométrie naturelle, depth_midas pour contraste) ou **openpose_hand** (keypoints de doigts) contraint bien mieux la main qu'un OpenPose corps seul. Modèles SDXL anime : NoobAI-XL ControlNet-OpenPose (Civitai 962537), Illustrious-XL ControlNet OpenPose (Civitai 1359846), xinsir/controlnet-openpose-sdxl-1.0 (présenté comme le plus performant par Stable Diffusion Art). Anima-LLLite-Regional-Controlnet (Sen-sou) illustre l'usage combiné ControlNet + Attention Couple pour associer prompt↔région ; à noter que ce modèle prévient que « generations involving distant subjects may not strictly adhere to the provided mask boundaries » (entraîné sur compositions rapprochées).

## Recommendations

**Étape 1 — Corriger le prompt (coût nul, à faire immédiatement).**
- Remplacer toute formulation NL type « reaching toward camera » par des tags Danbooru de pose de main fermés : `outstretched_hand, pov_hands` (POV vers caméra) ou `own_hands_together` selon la pose.
- Placer la pose de main dans le premier tiers du prompt (anti-dilution 248 tokens), avec les tags de main vide vérifiés.
- Négatif : `holding, holding object, object, phone, cellphone, cup, holding cup, bottle, camera` — mais ne pas s'y fier seul.

**Étape 2 — Renforcer la suppression (coût faible).**
- Installer `ChenDarYen/ComfyUI-NAG` et remplacer KSampler par `KSamplerWithNAG (Advanced)` ; appliquer NAG au négatif d'objets (`nag_scale` ~5 pour commencer). Benchmark : si le taux d'objets phantômes ne baisse pas nettement sur un échantillon de 200 images, monter `nag_scale` ou passer à l'étape 3.
- Complément possible : NegPiP via `ComfyUI-ppm`, `(holding,:-1.3) (object:-1.1)`.

**Étape 3 — Contrôle spatial (coût moyen, la solution robuste pour un dataset).**
- Générer, depuis le même guide Blender, un **masque de la paume** (la zone lisse problématique).
- Appliquer un conditionnement négatif régional (`ConditioningSetMask` sur `holding, object` limité au masque de paume, puis `ConditioningCombine`) OU Attention Couple avec région paume.
- En parallèle, dans `ComfyUI-Advanced-ControlNet`, passer un `mask_optional` qui **renforce** la force ControlNet sur la main.

**Étape 4 — Contraindre la géométrie de main sans complexifier le guide (coût moyen).**
- Ajouter un second ControlNet **depth** ou **openpose_hand** ciblé sur la main, avec `start_percent=0.0` et `end_percent≈0.85`.
- Utiliser des Timestep Keyframes pour garder la contrainte de main plus longtemps que la contrainte de corps.

**Étape 5 — Verrouiller le pipeline batch (coût moyen, indispensable pour un dataset reproductible).**
- TIPO/DanTagGen : renseigner `Ban tags` = `holding|object|cup|phone|cellphone|camera|bottle|weapon|gun`, température basse, format Kohaku-XL-Zeta figé, seed maîtrisé.
- `ComfyUI-stable-wildcards` pour la reproductibilité des wildcards.
- Versionner (git) un « prompt skill » : allowlist/banlist de tags, format canonique, réglages par checkpoint, few-shot examples ; l'injecter comme system prompt dans un LLM local (Qwen via Ollama) ou dans le champ Ban tags.

**Seuils de décision.** Mesurer le taux d'images à objet phantôme sur un lot de contrôle (≥200 images). Si >5% après étapes 1-2, passer à l'étape 3 (spatial). Si la géométrie de main reste incohérente après l'étape 3, passer à l'étape 4 (depth/openpose_hand). Pour un dataset de segmentation, viser <1% d'objets parasites, car chaque image erronée pollue le label de masque et dégrade le fine-tuning SAM.

## Caveats
- **Tags non confirmés** : `empty_hands`, `open_hand`, `spread_fingers`, `showing_palm` doivent être vérifiés directement sur danbooru.donmai.us/wiki_pages (existence/comptes exacts non confirmés ; les comptes cités proviennent d'un CSV d'autocomplete proxy potentiellement daté). `own_hands_together`, `outstretched_hand`, `outstretched_arm`, `interlocked_fingers`, `pov_hands` sont confirmés avec comptes.
- **Anecdote exacte** : le scénario précis « reaching toward camera → objectif photo halluciné » n'a pas été trouvé verbatim dans un thread unique ; le mécanisme (prior hand↔holding) et les correctifs sont bien documentés en agrégat, mais la formulation exacte du cas est une synthèse.
- **TIPO / ICLR 2026** : le dépôt KGen annonce « TIPO (ICLR 2026) » avec un lien OpenReview, mais aucune source tierce indépendante ne confirme l'acceptation ; à traiter comme annoncé par les auteurs. L'arXiv 2411.08127 et l'entraînement sur 30M entrées sont, eux, confirmés.
- **NAG** : le node natif ComfyUI `NAGuidance` a un bug report ouvert (Comfy-Org/ComfyUI #12707) sur certains modèles récents ; tester le repo `ChenDarYen/ComfyUI-NAG` sur SDXL/Illustrious avant prod. La page NeurIPS 2025 est confirmée.
- **MaskAttn-SDXL, EliGen** sont des travaux de recherche (nécessitent l'entraînement de têtes de masquage / des modèles spécifiques) — pas de node ComfyUI prêt-à-l'emploi confirmé à la date de recherche ; à considérer comme direction, pas comme solution immédiate.
- **Rythme d'évolution** : l'écosystème (versions ComfyUI, nodes, checkpoints) évolue très vite. Les numéros de version/nodes cités sont valides à la date de recherche (juillet 2026) et doivent être revérifiés.
- La plupart des guides « 2026 » cités (smartremotegigs, offlinecreator, apatero) sont communautaires/commerciaux ; leurs chiffres précis (ex. seuils VRAM) sont indicatifs, non évalués par les pairs. Les conventions start/end percent, en revanche, sont corroborées par la documentation officielle des nodes.
