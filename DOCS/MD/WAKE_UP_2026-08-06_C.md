## Comment reprendre le contrôle

1. **Vérifier l'avancement** : `DEMO/output/loop_log.txt` (dernières lignes)
   + `nvidia-smi` (RTX 5080 doit être active si une itération est en cours)
   + lister `DEMO/output/miku_demo_30s_v*.mp4` pour voir les blocs terminés.
2. **Arrêter proprement la boucle** (retour de Jérémy, ou avant toute
   décision de commit) : créer le fichier vide `DEMO/STOP_LOOP.flag` — la
   boucle le détecte entre deux itérations et s'arrête sans interrompre un
   run en cours. Pour un arrêt immédiat (kill), fermer la fenêtre `cmd`
   dédiée (repérable par son titre `py -3.12 DEMO\run_demo_loop.py`) — ne
   PAS tuer un autre process `python.exe`/`cmd.exe` sans avoir identifié
   lequel (plusieurs fenêtres cmd sont ouvertes sur cette machine, cf.
   convention `windows-detached-training-pitfalls`).
3. **Ne rien committer sans confirmation explicite de Jérémy** (règle du
   brief, déjà respectée cette session — aucun commit effectué).

## Limitation connue à garder en tête (pas un bug à corriger en urgence)

Le contrôle de caméra par phrase de prompt texte (zoom/orbite/gros-plan) a
un effet visuel **subtil**, pas un vrai mouvement de caméra net — attendu
d'un I2V ancré sur une image unique par clip. Ne pas rouvrir cette
investigation sans un plan concret (ControlNet/LoRA caméra dédié, hors
périmètre de cette session) — voir `DOCS/MD/DEMO_30S_MIKU_20260806.md`
section "Résultat" pour le détail.
